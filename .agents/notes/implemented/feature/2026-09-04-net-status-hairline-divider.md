# Agent Note: 网络状态表达改用发丝分隔线（替代中央 6px 柱状）

Status: implemented

## Problem

胶囊/贴边条中央用 6px 宽竖向柱状（4px 色芯 + 两侧边线）表达公网连通质量，
用户反馈该“柱状”视觉过重：它在 CPU/MEM 数字之间形成一条高对比色块，
抢夺注意力，且与两侧进度填充的色块语言冲突（状态色出现三处）。

约束：胶囊高仅 40px、贴边条仅 10px；网络状态只是辅助信息，
详情（延迟毫秒）已有 hover tooltip；颜色语义（绿/ amber/红 / 检测中灰）
沿 SPEC-032 已被用户接受，只需换形态、不换语义。

## Decision

采用「状态即分隔线」：删掉中央柱状，还原为一条发丝分隔线，
分隔线本身用状态色着色（good 绿 / poor amber / offline 红，
线宽细改用 500 系提亮保证存在感，检测中 white/20 保证分隔永不消失），
poor/offline 保留呼吸脉动。
`NetDot` 的 `variant="bar"` 由 `variant="hairline"` 取代，
`CapsuleBar` / `EdgeBar` 同步切换；`bar` 形态无消费者后整体删除
（含 CSS 与注释），不保留怀旧分支。

**修订二（2026-09-04，用户反馈：2px 太细、希望随速率动态变化）**：
线宽 2px→3px；长度按总速率（↓+↑）对数映射动态伸缩（40%→80% 高度，
1MB/s 封顶，CSS 0.7s 过渡平滑轮询步进），颜色保持质量色系不变、
仅不透明度随活跃度呼吸（静默变暗、忙时提亮），tooltip 在线时追加
↓/↑ 实时速率。颜色已承载质量语义，不再叠加速度语义以免歧义。
数据流：`CapsuleWindow` 从 `useMonitor()` 取 `netDownBps/netUpBps`，
经两个 Bar 透传至 `NetDot`（`downBps/upBps`，null = 未知→中性等级）。

发丝线高度沿用旧柱状的父级控制（胶囊 `h-5` 居中 / 贴边条 `h-full` 通高），
morph 仍是文档流内 flex 子元素，随容器缩放天然连续，无需绝对定位补丁。

## Alternatives considered

- 回退中央圆点 + 1px 分隔线（2026-08-26 之前形态）：
  正是被用户反馈替换掉的形态（圆点 + 线两个元素仍显忙），回退等于复活已否决项。否决。
- 保留柱状但减到 2–3px / 降透明度：
  只是把“柱”变细，仍是独立色块元素，信息密度未减；且细柱 + 两侧边线在
  10px 贴边条里渲染发虚。否决。
- Wi-Fi 弧形 glyph（语义图标，12px 单色）：
  语义最直白，但 10px 贴边条内容纳弧线图标过挤，且引入新 SVG 资产与
  “图标 vs 进度条”两种视觉语言并存；可作为将来 poor/offline 强化时的备选。否决（本次）。
- 仅异常时显形（good 状态完全隐藏分隔着色）：
  最极简，但 good 与“检测中”无法区分，用户会误判探测故障；保留 good 着色，
  用颜色恒定存在保证可信度。否决（本次）。
- 颜色随速率变色（如 idle 灰 → 忙时绿）：
  颜色已有质量语义（绿=连通好），再叠速度语义会产生“变灰=断网？”的歧义；
  速度改由长度 + 明暗两个无语义冲突的通道表达。否决。
- 长度线性映射速率：
  日常区间（KB/s 级）会被下载峰值（MB/s 级）压扁到几乎无变化；
  对数映射让静默/涓流/浏览/下载四档都有可见区分。否决线性、采用对数。

## Consequences

- 中央视觉重量从 6px 色块降为 3px 发丝线；颜色契约（SPEC-032 三族 + 检测中灰）
  与 tooltip 文案不变，用户已学到的颜色语义零迁移成本；tooltip 追加的 ↓/↑
  速率与面板 NET 行同口径（B/s→KB/s→MB/s，offline 不混显全接口速率）。
- `NetDot` 仅保留 `dot`（面板 NET 行）与 `hairline` 两种形态；若将来用户仍不满意，
  恢复条件：任一新形态需先在胶囊 40px / 贴边 10px 双高度下证明不抢数字视觉，
  否则不引入第三形态。
